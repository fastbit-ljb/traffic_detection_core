# 答辩演示流程

## 演示前准备

1. 启动后端和前端，确认 `/health` 返回 `healthy` 或 `degraded` 且 `vehicle_detector=true`。
2. 打开前端，在“数据管理”确认已激活 YOLOv8n 模型；推理设备优先使用 CUDA。
3. 准备 `test_images/1.jpg` 与 `test_samples/kitti_road_traffic.mp4`。视频文件需在答辩电脑上预先试跑一次。
4. 打开“检测记录”并清空与演示无关的历史数据，保留至少两个可删除的演示记录。
5. 同时保留浏览器的 OpenAPI 页面 `http://127.0.0.1:8000/docs`，用于老师追问接口时展示。

## 演示脚本（约 6 分钟）

### 1. 正常图片检测（约 1 分钟）

操作：进入“图片检测”，上传 `test_images/1.jpg`，开启“保存到检测记录”，点击检测。

讲解：

> 系统先校验文件类型和大小，然后调用 YOLOv8n 识别行人、汽车、公交车和卡车。页面不仅显示目标框和置信度，还把目标中心点映射到四个归一化车道区域，返回分类数、车道数和处理时间。检测完成后，原图和标注结果被作为一条可追溯记录保存。

观察点：检测结果图、四类计数、车道统计、处理耗时、历史记录新增。

### 2. 基准线与进出统计（约 45 秒）

操作：在图片或视频任务中开启基准线，设置“水平线、向下、50%”，再次提交。

讲解：

> 基准线位置使用 0 到 1 的归一化坐标，适用于不同分辨率。视频帧中系统按同类别最近中心点关联目标，当中心点跨越基准线时，依据方向累加进入或离开数量。这里采用轻量统计机制，适合交通流量展示，不把它夸大为复杂的多目标跟踪算法。

观察点：标注媒体中的红色基准线，结果中的 `flow_counts.entry` 和 `flow_counts.exit`。

### 3. 视频后台任务（约 2 分钟）

操作：进入“视频任务”，上传 `test_samples/kitti_road_traffic.mp4`，保持基准线开启，点击开始处理。

讲解：

> 视频处理不阻塞页面。提交后接口立即返回任务 ID，后台逐帧检测，每十帧更新一次进度，并通过 WebSocket 将进度、当前分类数量和跨线统计推送到前端。刷新页面后，任务状态仍可由 SQLite 恢复查询；完成后可以播放浏览器兼容的标注视频。

观察点：`queued -> running -> completed` 状态、进度条、分类/进出统计、输出视频播放。

### 4. 历史详情与多选删除（约 1 分钟）

操作：进入“检测记录”，点击一条图片记录查看原图、标注图和统计；勾选两条记录，点击“删除选中”，在确认对话框点击确认，然后刷新列表。

讲解：

> 历史记录保存来源、模型、分类统计、处理时间以及原图和标注结果。批量删除以记录 ID 为准，数据库记录删除后后端只清理应用生成目录中的关联媒体，不会删除任意用户文件。因此页面和服务器保存的演示结果保持一致。

观察点：详情弹窗、复选框、删除确认、列表立即减少、刷新后记录不恢复。

### 5. 异常处理（约 45 秒）

操作：尝试上传 `.txt` 文件作为图片，或在 OpenAPI 页面调用图片接口并传入无效基准线组合，例如 `baseline_orientation=horizontal`、`baseline_direction=left`。

讲解：

> 系统在进入推理前校验文件类型、大小和基准线参数。无效输入返回 400，而不是进入模型或生成错误记录。视频格式、模型 `.pt` 后缀、数据集 ZIP 和任务 ID 也使用相同的明确错误策略。

预期：界面或 OpenAPI 显示“文件类型不支持”或“进出方向与基准线不匹配”，检测历史不新增。

## 答辩追问的简短回答

| 问题 | 回答 |
|---|---|
| 为什么选择 YOLOv8n？ | 在同一 300 张验证集、10 轮训练条件下，YOLOv8n 的 mAP50-95 为 28.04%，默认阈值下 F1 为 58.97%，推理 8.36 ms/图，GPU 峰值约 32 MiB，精度-速度-资源最均衡。 |
| 为什么阈值默认是 0.40，不是 F1 更高的 0.25？ | 0.25 的 F1 为 59.79%，但误检更多，Precision 仅 64.40%；0.40 的 Precision 升至 78.58%，更适合界面展示和减少错误告警。统计场景可选 0.25。 |
| 进出统计如何实现？ | 目标中心点在相邻帧按同类别最近距离关联；跨越可配置基准线时按方向计入 entry 或 exit。它是轻量业务统计，不是复杂 MOT 算法。 |
| 删除为什么可信？ | 前端调用批量删除 API，后端删除 SQLite 元数据后，仅清理 `output_images/` 和 `output_videos/` 的关联应用媒体；测试覆盖了不删除外部文件的边界。 |
| 项目创新点在哪里？ | 创新在业务闭环：四类检测扩展到车道/进出统计，视频异步任务与实时进度，历史结果可追溯并支持安全删除，以及基于真实实验的模型部署选型。 |

## 录屏素材清单

1. 首页或实时检测页面：模型、设备和健康状态。
2. 一张图像的原图与标注结果。
3. 开启红色基准线的检测画面和进出统计区域。
4. 视频任务运行中和完成后的画面。
5. 历史详情弹窗、全选、多选删除确认和删除后的空状态。
6. 无效文件或无效基准线的错误提示。
